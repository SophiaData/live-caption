# 架构与技术约束

> 维护人：技术合伙人。老板不需要读本文件。版本以 lockfile 为准，本表只记选型与理由。

## 技术栈

| 层 | 选型 | 一句话理由 |
|---|---|---|
| 语言/运行时 | Python 3.12（本机 ~/.local/bin/python3.12；打包时捆绑） | 音频/网络生态最全；GUI、捕获、协议层全用它 |
| GUI | PySide6 6.12（Qt6） | 成熟桌面 GUI，无边框置顶透明窗 + 菜单栏常驻一套搞定，双平台 |
| 音频捕获 | Mac：ScreenCaptureKit（系统级，免驱动，macOS 13+）/ 备用 BlackHole（macOS<13）；Windows：WASAPI loopback；统一经 sounddevice 层封装 | 苹果官方路径零安装体验最佳；BlackHole 保留给老系统；Windows 原生支持 |
| 网络 | httpx 0.28 | 同步/流式/可取消请求齐全，覆盖 OpenAI 兼容翻译 API 与分段识别 API |
| 配置存储 | SQLite（用户目录内单文件）+ 系统钥匙串存密钥 | 零服务、零依赖；密钥不落明文 |
| 测试 | pytest（GUI 逻辑与管道层可测，Qt 部分冒烟） | 主流保守 |
| 工具链 | ruff（format+lint）+ mypy + pytest 单命令串联 | agent 友好：类型检查强、报错可读 |

## 硬约束（动架构、加依赖前逐条核对）

- **发布产物只支持 Apple Silicon（arm64）+ macOS 13+**（老板 2026-11-03 定：不做 Intel、不做 universal2）。这条由机器保证，不是文档承诺：构建前解释器门 + spec 守卫 + 构建后产物架构门，见 ADR 18/19 与 `make check-arch` / `make verify-arch`
- 依赖白名单制：新依赖必须在下表登记用途与理由；无理由不引入
- 黑名单：不引入任何需要编译环境的重依赖（构建机之外）
- **例外（2026-10-22 老板裁决）**：允许引入 faster-whisper（本地识别，可选方案）。理由：用户不愿注册云端账号时，本地识别是唯一免费可用路径；作为「可选项」与云端配置并存，不改变「用户自配模型」主定位。模型文件按需下载，不进安装包
- 模型接入只走「OpenAI 兼容协议」两种端点（chat/completions、audio/transcriptions）；厂商特有协议一律用适配层收编，不进核心管道。**本地识别经内部接口适配成同一 Recognizer 接口**，管道层无感
- 网络层：所有请求必须可取消、必须有超时；禁止无界重试（上限 3 次、指数退避）
- 管道层：各段用有界队列连接；UI 线程与音频线程、网络线程严格分离，UI 卡死 = P0 缺陷
- 日志：本地文件日志，禁止打印密钥；日志单文件上限 10MB 滚动
- 错误处理口径：用户可见错误一律给「人话 + 下一步怎么办」；技术细节进日志

## 决策记录（ADR-lite：只记「为什么」，防止日后翻案无据）

| # | 日期 | 决策 | 理由 | 被否的替代方案及原因 |
|---|---|---|---|---|
| 1 | 2026-10-21 | Python + PySide6 而非 Tauri/Electron | 音频捕获、协议适配生态全在 Python；Tauri 要 Rust sidecar 双技术栈，Electron 体积大 | Tauri（壳小但双栈维护贵）、Electron（体积违背「轻量」定位） |
| 2 | 2026-10-21 | 模型接入只认 OpenAI 兼容协议 | 一个协议覆盖 DeepSeek/Kimi/通义/OpenAI/中转站/Ollama，用户填 base_url 即用，厂商中立 | 各厂商私有 SDK（维护面爆炸、加引擎要改核心） |
| 3 | 2026-10-21 | Mac 音频捕获主路线用 ScreenCaptureKit（免驱动） | 老板拍板：公开发布不能要求用户装驱动；SCK 只需首次授权"屏幕录制"权限（只用声音不录画面） | BlackHole 主路线（要求装第三方驱动，劝退用户）→ 降级为 macOS<13 备用路线 |
| 4 | 2026-10-21 | 识别走「VAD 断句→分段识别」而非流式识别协议 | 第一版延迟目标 2 秒内，分段方案延迟可达标且代码量减半；流式协议各家不兼容 | 各家流式 WS 协议（MVP 过重，记 tech-debt 待议） |
| 5 | 2026-10-21 | VAD 用能量阈值 + 静音时长断句，先不引 Silero | 零依赖即可达成 2 秒目标；观感不佳再升级（tech-debt 跟踪） | Silero VAD（引 ONNX 运行时，违背轻量，先不上） |
| 6 | 2026-10-21 | 配置存 SQLite + 钥匙串 | 本地软件定位，无账号无云；密钥安全是公开发布的基本要求 | 明文 JSON（不安全）、云同步（违背 PRD「不做账号」） |
| 7 | 2026-10-22 | 识别新增「本地 faster-whisper」作为可选方案（与云端 API 并存） | 老板裁决：不强迫用户注册云端账号；本地识别零成本零注册，符合"不要求用户额外配置"的一贯原则 | 只做云端 API（有 key 门槛，违背产品调性）、只做本地（体积重、首启需下载） |
| 8 | 2026-10-22 | 本机为 x86_64（非 Apple Silicon），本地 Whisper 只能 CPU 跑 | 实测环境限制；CPU 跑 small 模型可近实时，但 large 模型会很慢。UI 需提示性能预期 | 无（硬件事实） |
| 9 | 2026-11-02 | 延迟观测用「可注入 LatencyTracer + 可注入时钟」，只记内存时间戳 | PRD 2 秒硬指标从没测过（Issue #16）：要在不改动行为/线程模型、不在音频热路径做 I/O 的前提下分阶段计时；时钟可注入让确定性基准用假时钟零真实等待、可复现 | 直接埋 time.monotonic 硬编码（基准不可复现且要真等）；日志文件打点（热路径阻塞 I/O，违背约束）；改识别参数"顺手优化"（越权，参数裁决属 TD-1/TD-2） |
| 10 | 2026-11-02 | 「说完」锚点取 断句打点时刻回退句尾静音确认时长（Utterance.trailing_silence_s） | 静音确认按实时到达，本句的分段确认延迟不受「处理前一句时喂入暂停」等跨句节奏污染；确定性基准逐句串行也能出可复现的五段拆分 | 用全局捕获原点+音频时间轴映射（喂入一暂停就串味，第 2 句起分段数虚高——已实测踩坑后改掉） |
| 11 | 2026-11-03 | 「边说边出」用**现有非流式接口的更短子窗口多次调用**模拟流式观感，不实现任何供应商流式协议 | Issue #17 老板明确约束：TD-2 已写明各家流式协议不通用，做了就被绑一家；用子窗口提前送识别即可达到「字幕跟着人走」的观感，管道与协议层零改动 | 上 WebSocket 流式（架构裁决，且绑定单一供应商） | 
| 12 | 2026-11-03 | 草稿走**独立队列 + 定稿优先**：**已入队**的整句永远比草稿先被取走；整句队列非空时草稿直接丢弃；同一句只保留最新草稿；定稿上屏后迟到的草稿作废；草稿绝不送翻译。已知残留：正在识别中的那条草稿取消不了（Recognizer 无 cancel），故定稿最多多等**一次识别调用**（草稿音频比整句短，通常也更短）；要消掉它需要可取消的识别请求或真流式，见 TD-8 | 实测 LIVE 中位 5.49s、排队 0.02→4.04s 持续累积（Issue #17 追加要求 2）：草稿是「锦上添花」，绝不能把已有延迟拖坏；也满足「草稿不送翻译槽位」的额度约束 | 草稿与定稿共用一条 FIFO 队列（定稿会排在草稿后面，排队恶化）；草稿也送翻译（额度直接翻倍） | 
| 13 | 2026-11-03 | 草稿参数集中在 `DraftConfig`（enabled/silence_ms/max_s/min_s/max_per_utterance），引擎默认关、产品层默认开 | 设计约束「不许写死魔法数」+「不得改变现有线程模型/既有行为」：默认关闭让 Issue #5/#6/#16 的既有 122 条用例与行为逐字不变，产品默认开启由偏好（`draft_enabled`）与设置面板驱动 | 把阈值写死在断句器里（改不动、也无法验收参数可调）；引擎默认开启（会改掉既有测试的期望值） | 
| 14 | 2026-11-03 | 草稿与定稿用同一个 `utt_id` 对齐，字幕窗**同一对标签原地替换**，并按 utt_id 丢弃迟到的旧草稿 | 验收硬要求「绝不出现两条字幕」「定稿一定覆盖草稿」；给字幕窗加 `entry_count()` 不变量，让「追加新行」这种退化被测试当场抓住 | 每条草稿新建一个标签/一行历史（会出现两条字幕，且要做历史导出，属 M2 范围） | 
| 15 | 2026-11-03 | 观测扩展只加不改：草稿时刻登记进定稿那条记录的 `draft_shown_at`，`STAGES` 五段语义与行格式逐字保留；报告把「说完→原文出现」与「说完→译文出现」分开输出 | Issue #17 硬性禁止「不动 #16 引入的时间戳语义」；实测原文 ≈2s 而译文 ≈5s，混成一个 total 就看不出产品到底哪一头不达标 | 新增一个 STAGES 元素（会破坏「打点齐全才算完成句」的既有判定与完成数口径）；用 total 代表一切（看不清达标的到底是哪一头） | 
| 16 | 2026-11-03 | 草稿只在**大概率比定稿更早出现**时才送识别：断句器给每条草稿标 `draft_lead_s`（比预计定稿早多少秒）与 `draft_trigger`，管道按实测识别耗时（滑动均值）判断——提前量不够就主动省掉，不烧额度也不占 worker | 真服务实测 `make latency LIVE=1 --draft` 第二遍抓到排队恶化：关闭 中位 0.05s → 开启 中位 1.68s。根因是停顿触发的草稿天生只比整句判定早 0.15s（整句静音阈值 − 草稿静音阈值），而一次识别要 0.2~1.8s：这类草稿换不来更早的字，却让紧随的定稿多等一次调用，过切（TD-9）又把放大效应吃进累计延迟 | 写死一个「识别必须快于 X 毫秒才出草稿」的魔法阈值（服务一变就错）；或给草稿单独开线程池（违反「不得改变现有线程模型」）；或干脆取消停顿触发（连续说话的场景就没用了） | 
| 17 | 2026-11-03 | 整句一旦排起队就**自动停补草稿**，队列清空后恢复（`draft_paused`）；管道计时时钟可注入 | 第 5 轮真服务实测（同机同模型、单跑不并发）：关闭 排队中位 0.03s → 开启 2.37s。单 worker 串行 + 调用不可取消，草稿在途时紧随的整句只能等——所以「追不上了就先不加戏」必须是运行时自适应规则，而不是靠人记得关开关。时钟可注入是因为原有用例靠 `time.sleep` 造慢服务，CI 上 sleep 精度不够会飘（macos-14 实测红过一次） | 让草稿和定稿抢同一条队列的先后顺序（改不动排队本质）；给草稿单独开线程（违反「不得改变现有线程模型」）；用墙钟 sleep 写慢服务用例（CI 飘） | 
| 18 | 2026-11-03 | Apple Silicon 架构由**三道机器门**保证（Issue #20）：① `make check-arch` 断言构建解释器是 arm64（非 darwin 自动跳过，`ALLOW_INTEL=1` 只能显式绕过且打印「已绕过」）② `live-caption.spec` 顶部 `guard_interpreter_for_build()`——绕过 make 直接跑 pyinstaller 也一样中止 ③ `make verify-arch` 逐个校验 `.app`：主程序必须**只有 arm64**，每个 `.so`/`.dylib` 必须**含 arm64**（universal2 的 Qt 轮子含 arm64 即放行；认不出架构的文件算不合格，不静默跳过） | 以前架构全靠 `runs-on: macos-14` 这一行碰运气，流水线里 grep 不到任何架构断言，runner 一换型就静默产出「装得上、跑不动」的 Intel 包。判读用**自己解析 Mach-O 文件头**（`app/release/macho.py`，只读头部几十字节）而不是调 `lipo`：门要能在任何机器上用合成字节做单元测试，也不把发布判定绑在 Xcode 工具链上；CI 仍原样打印 `lipo -archs` 作交叉印证的发布证据（本机实测两边结论一致）。产物名里的架构取自 `lipo` 对**成品主程序**的实测结果，不写死字符串，名字不会骗人 | 只靠 `runs-on` 选型号（无保证）；用 `lipo`/`otool` 实现门（绑 Xcode、测不了）；把 "arm64" 写进产物名（产物是 Intel 也照样叫 arm64）；认不出架构就跳过（等于给门开后门） | 
| 19 | 2026-11-03 | PyInstaller 显式 `target_arch="arm64"`，`codesign_identity` 保持 None，签名走 CI 里独立的 ad-hoc 步骤 `codesign --force --deep --sign -` | 老板已定只做 Apple Silicon：`target_arch="arm64"` 让 PyInstaller 把启动器 thin 成 arm64，拿不到 arm64 切片就直接报错（`target_arch=None` 的语义正是「跟着构建机走」）。项目没有 Apple Developer 身份，用 `codesign_identity` 会假装签名；ad-hoc 是 Apple 芯片上 arm64 二进制能跑起来的最低要求。**公证（notarization）不在范围**：要 $99/年 账号，`spctl --assess` 实测仍 rejected，用户首次打开需「仍要打开」（见 TD-11） | universal2（老板明确不做）；`target_arch=None`（=现状的问题本身）；在 spec 里填 `codesign_identity`（没有该身份，且会把发布绑到某个证书上） | 

## 目录结构约定

```
live-caption/
├── app/                  # 主包：入口 main.py 在此
│   ├── capture/          #   音频捕获（Mac/Win 设备抽象）
│   ├── pipeline/          #   断句→识别→翻译管道（纯逻辑，可测；含 trace.py 延迟观测缝）
│   ├── bench/             #   make latency 基准（假时钟假件 + LIVE 真服务，不进产品运行时路径）
│   ├── build/             #   make check-arch / verify-arch 的架构门（Mach-O 解析，Issue #20；不进产品运行时路径）
│   ├── providers/        #   OpenAI 兼容协议客户端（asr/translate 两槽位）
│   ├── ui/               #   PySide6 界面（悬浮窗/配置向导/托盘）
│   └── config/           #   SQLite 配置 + 钥匙串
├── tests/                #   pytest：管道与协议层为主
├── docs/                 #   PRD/架构/台账/协作手册（老板读物在 docs/）
├── backups/              #   改核心文件前的备份（不入 git）
└── dist/                 #   打包产物（不入 git）
```
